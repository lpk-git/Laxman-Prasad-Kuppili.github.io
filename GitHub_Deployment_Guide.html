🚀 Simple Guide: Launching Projects with GitHub & AI Tools

A step-by-step manual for non-technical creators.

1 How to Set Up a Repository on GitHub

Think of a repository (repo) as a master folder in the cloud where your project lives.

  • Go to GitHub.com and log in to your account.
  • Click the "+" icon at the top right of the screen and select "New repository".
  • Give your repository a short, clear name (e.g., my-new-website).
  • Choose "Public" (this is required if you want others to see the website for free).
  • Check the box that says "Add a README file". This creates an initial starting point for the folder.
  • Click the green "Create repository" button at the bottom.

2 Deploy the Project (Making it Live!)

Deploying means taking your project files and putting them on a public web address for the world to see.

  • On your new repository page, click the "Settings" tab (the gear icon near the top right).
  • On the left-hand sidebar, scroll down and click on "Pages".
  • Under the "Build and deployment" section, look for the "Source" dropdown. Ensure it says "Deploy from a branch".
  • Right below that, under "Branch", change the dropdown from "None" to main (or master).
  • Click "Save".
💡 Why are we doing this?
GitHub Pages is a free service that hosts your website. By changing these settings, you are telling GitHub: "Please take the files in my 'main' folder and turn them into a live, public website." After a few minutes, a web link will appear at the top of that page (e.g., https://yourusername.github.io/my-new-website).

3 Connecting Your Repo to an AI Tool (like AntiGravity or Kiro)

The AI needs access to your folder so it can write and edit code for you.

  • Go back to your repository's main page on GitHub and click the green "<> Code" button.
  • Copy the web link provided (it usually ends in .git).
  • Open your AI Tool (like AntiGravity or Kiro).
  • Look for a section called "Source Control", "GitHub", or "Workspace".
  • Select the option to "Clone" or "Open" an existing repository.
  • Paste the link you copied from GitHub.
  • The tool will likely ask you to log in to GitHub to authorize access. Follow the prompts on the screen.
💡 Why are we doing this?
This synchronizes your AI tool with your GitHub master folder. Now, when the AI generates or edits code for you, it is writing those files directly into your project!

4 Saving Your Work (Committing Changes)

In the software world, "saving" your progress is called committing.

  • Once the AI has created or updated files for you, you need to save these changes back to the cloud (GitHub).
  • Go to the Source Control tab in your AI tool. You will see a list of files that were changed.
  • Look for a text box labeled "Message" or "Summary". Type a brief description of what was done (e.g., "Added a new homepage design").
  • Click the "Commit" button.

Push vs. Sync: What's the difference?

After clicking Commit, you must send your changes to the cloud. You will usually see an option to Push or Sync.

  • Push (One-Way Street ⬆️): This simply takes your locally saved changes and uploads them straight to GitHub. Use this if you are the only person working on the website.
  • Sync (Two-Way Street ⬇️⬆️): This first downloads any new changes from GitHub that you might not have on your computer yet, and then it uploads your new changes. Use this if multiple people (or multiple AI tools) are working on the project at the same time to prevent breaking things.
💡 Why a message?
The summary message acts like a sticky note in your project's history. It ensures you and the AI always remember exactly what changed on what day and why.

5 Making Sense of the Settings Sidebar

When you click on the Settings tab in GitHub, the left sidebar is packed with technical options. You don't need most of them, but here is a simple translation of the most common ones:

  • Branches: Think of a branch like an alternate timeline. You can create a "test" branch to experiment with a new design without accidentally breaking your live "main" website.
  • Actions: A tool for creating robots that automatically do chores for you (like automatically testing your code every time you save).
  • Secrets and variables: A highly secure digital vault. If your website needs a password to connect to a database, you store the password here so hackers can't see it in your code.

🔌 Webhooks (The Digital Tap on the Shoulder)

What is it? A Webhook is a way for GitHub to instantly notify another application the exact second something happens in your project.

Example Usage: Let's say you have a team chat on Slack. You can set up a Webhook in GitHub and paste a special URL provided by Slack into it. You tell the Webhook: "Every time someone Pushes new code, send a message to this URL."

Now, whenever your AI tool finishes a job and you Push the code, your entire team's Slack channel instantly dings with a message: "New updates are live!" No one has to check GitHub manually; the apps talk to each other automatically.

✉️ Email Notifications

What is it? A simple way to receive an email in your inbox when specific events occur in your repository.

How to set it up: Click on Email notifications in the sidebar. You will see a box where you can type in up to 2 email addresses. You can then check boxes to decide what triggers an email (e.g., when someone "pushes" code, or when someone opens an "Issue").

Example Usage: Imagine you build a website and allow users to report bugs (GitHub calls these Issues). Instead of constantly logging into GitHub to check if anyone reported a bug, you can set up Email Notifications. Now, the moment a user submits a bug report, you get an email directly to your phone saying, "Hey, a new bug was reported on your site."

You're all set! Keep this guide handy for your next big project. 🚀
