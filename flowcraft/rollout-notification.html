Ready-for-Rollout Notification

Jira Automation Webhook JSON Power Automate Adaptive Cards Microsoft Teams

Overview

This automation provides instant, structured visibility when a Jira issue transitions to a "Ready for Rollout" status. Rather than relying on someone remembering to send a manual message, the notification is triggered automatically and delivered to the relevant Microsoft Teams channel the moment the status changes — with all the key details the team needs to act.

The Problem

When work became ready for rollout, the people who needed to know — release managers, ops teams, or squad leads — were not always aware in a timely manner. The typical approach involved manually sending a Teams message, tagging the right people, and including the relevant Jira details by hand.

This created several friction points:

  • Notifications were inconsistent — some issues got missed entirely
  • Manual messages varied in format and detail level
  • There was a delay between the status change and the notification
  • The person making the status change had to remember to also send the message

Trigger

The automation fires when a Jira issue transitions to the configured Ready for Rollout status. This is the single entry point — the entire downstream flow is driven by this one status change in Jira, requiring no additional action from the team member making the transition.

Payload / Data

The JSON payload built by Jira Automation carries the following fields to Power Automate:

Issue Key issueKey
Summary summary
Assignee assignee
Assigned Team team
Current Status status
Jira Issue Link issueUrl
Timestamp transitionTime

Processing Logic

  1. 1 Receive Webhook: Power Automate's HTTP trigger receives the POST request from Jira Automation and parses the JSON body.
  2. 2 Extract Fields: Dynamic content expressions pull the required values from the payload — issue key, summary, assignee, team, status, link, and timestamp.
  3. 3 Compose Adaptive Card: The extracted values are inserted into an Adaptive Card JSON template. Adaptive Cards produce a structured, visually formatted message in Teams — not a plain text block.
  4. 4 Post to Teams: The "Post adaptive card in a chat or channel" action delivers the card to the designated Teams channel. The channel can be a general delivery channel or squad-specific (combining with UC-02 routing logic).

Technologies Used

Jira Automation Trigger and payload builder — fires on the "Ready for Rollout" status transition and constructs the JSON payload.
Webhook HTTP POST transport — delivers the JSON payload from Jira to the Power Automate trigger endpoint.
JSON Structured payload format — carries all issue fields from Jira Automation to Power Automate.
Power Automate Processing and formatting layer — receives the webhook, parses the payload, builds the Adaptive Card, and posts to Teams.
Adaptive Cards Structured Teams message format — provides a clean, visually consistent notification layout instead of plain text.
Microsoft Teams Delivery channel — where the Adaptive Card notification is posted for the relevant team to see and act on.

Business Value

⚡ Instant Visibility Relevant people are notified the moment the status changes — no delay, no manual step.
📐 Consistent Format Every notification has the same structure and fields — easy to read and act on every time.
🔕 Zero Manual Effort The person transitioning the issue doesn't need to remember to notify anyone separately.
🔗 Direct Link to Jira The Teams card links directly to the issue — one click to the full context without searching.

Security & Privacy Notes

When implementing this automation, the following considerations apply:

  • The Power Automate HTTP trigger URL functions as a secret endpoint — it should be stored securely and not committed to version control or shared publicly.
  • Only include fields in the JSON payload that are necessary for the notification — avoid sending surplus issue data.
  • Ensure the Teams channel receiving notifications has appropriate membership — only people who should see rollout-ready items should have access.
  • No credentials, API keys, or tenant-specific identifiers should appear in the Jira Automation rule configuration in plain text.
  • Review whether issue summaries may contain sensitive or confidential information before routing them to shared channels.
