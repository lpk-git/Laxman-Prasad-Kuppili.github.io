Automated Sprint Completion Summary

Jira Automation Jira Smart Values lookupIssues Webhook JSON Power Automate Microsoft Teams

Overview

This automation eliminates the manual work of sprint completion reporting. When a sprint closes in Jira, the entire summary — metrics, counts, and dates — is collected, formatted, and delivered to the team in Microsoft Teams without anyone lifting a finger.

The Challenge

Sprint completion reporting required manually retrieving delivery metrics from Jira and communicating the results to the team. This created repetitive effort sprint after sprint, introduced inconsistency in how results were presented, and delayed the team's visibility into what was actually delivered.

Automation Goal

Automatically capture sprint delivery data the moment a sprint completes and publish a structured, consistent summary to the team's Microsoft Teams channel — with zero manual intervention.

How It Works

  1. 1 Trigger: A Jira Automation rule is configured to fire when a sprint transitions to "Completed".
  2. 2 Collect Metrics: Jira Smart Values and lookupIssues are used to query the sprint's issues and aggregate counts by type — stories, bugs, tasks, spikes — and sum story points.
  3. 3 Build Payload: The rule constructs a structured JSON object containing all sprint metrics, dates, and contextual fields.
  4. 4 Send via Webhook: The JSON payload is sent as an HTTP POST request to a Power Automate HTTP trigger endpoint.
  5. 5 Parse & Format: Power Automate receives the payload, parses the JSON, and formats the content into a readable Teams message or Adaptive Card.
  6. 6 Publish to Teams: The formatted sprint summary is posted to the designated Microsoft Teams channel, making it immediately visible to all team members.

Key Data / Metrics

The JSON payload captures the following sprint data points:

Sprint Goal
Story Count
Bug Count
Task Count
Spike Count

Story Points
Sprint Start Date
Sprint End Date

Technologies Used

Jira Automation Automation rule engine — triggers on sprint completion and orchestrates the entire flow.
Jira Smart Values Dynamic data references within the automation rule — used to extract sprint name, goal, dates, and issue fields.
lookupIssues Jira Automation function — queries sprint issues by type to produce aggregated counts and totals.
Webhook HTTP POST transport — carries the JSON payload from Jira Automation to the Power Automate endpoint.
JSON Structured data format — the sprint metrics payload built by the automation rule and consumed by Power Automate.
Power Automate Integration and formatting layer — receives the webhook, parses the JSON, and composes the Teams message.
Microsoft Teams Delivery channel — where the formatted sprint summary is published for the team to see.

Result / Value

⏱️ Time Saved Eliminates manual effort every sprint — no more pulling numbers from Jira by hand.
📐 Consistency Every sprint summary follows the same format, making results comparable over time.
⚡ Instant Visibility Summary is published to Teams the moment the sprint completes — no delay.
🔁 Repeatable Runs automatically every sprint with no configuration needed after initial setup.
