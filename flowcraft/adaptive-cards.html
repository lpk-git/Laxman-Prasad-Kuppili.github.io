Dynamic Microsoft Teams Adaptive Cards

Jira Webhook JSON Power Automate Adaptive Cards Microsoft Teams

The Challenge

Automation-generated notifications often begin as plain text messages posted to a Microsoft Teams channel. While functional, plain text has significant limitations as the volume and complexity of notifications grows:

  • No visual hierarchy — all information has equal weight, making it hard to scan quickly
  • Labels and values are mixed together in free text, requiring careful reading
  • No interactive elements — links, buttons, or actions cannot be embedded
  • Inconsistent formatting across different automation authors or rule changes
  • Difficult to extend — adding new fields means rewriting the message string

Solution

Power Automate dynamically constructs a Microsoft Teams Adaptive Card using data received from Jira via a webhook. Rather than building a plain text string, the flow maps each incoming JSON value to a named field in a structured card template.

The result is a notification that is visually consistent, easy to scan, includes a direct link to the Jira issue, and can be extended with new fields without restructuring the message format.

Dynamic Data Mapping

Each field in the incoming JSON payload is mapped to a named placeholder in the Adaptive Card template. Power Automate's dynamic content expressions bind the values at runtime — the card structure stays constant while the data changes with each event.

Field JSON Key (example) Card Element
Issue Key issueKey Header link, Issue row
Summary summary Summary row

Reusability

The Adaptive Card pattern established here is not specific to any single use case. The same card template and data-mapping approach can be applied across all Flow Craft automations — and beyond:

UC-01 — Sprint Summary Replace plain sprint metrics text with a structured card showing counts, story points, and sprint dates in labelled rows.
UC-03 — Rollout Notification The rollout card already uses this pattern — structured fields, status badge, and a "View in Jira" button.
UC-04 — Bug Alert The bug alert card applies priority-conditional formatting — the same Adaptive Card JSON supports colour-coded badges per priority level.
Any Jira → Teams flow Any future automation that posts to Teams benefits from this pattern — the card template is generic and payload fields are swapped per use case.

The key principle: define the card structure once, vary only the data. Adding a new field means adding one row to the template — not rewriting the notification logic.

Technologies Used

Jira Event source — the origin of the automation trigger and the data included in the payload.
Webhook Transport mechanism — carries the JSON payload from Jira to the Power Automate HTTP trigger endpoint.
JSON Payload format — the structured data object received by Power Automate, with one key per card field.
Power Automate Processing layer — parses the JSON, maps dynamic values, constructs the Adaptive Card, and delivers it to Teams.
Adaptive Cards Card framework — a JSON-based schema for structured, interactive messages rendered natively inside Microsoft Teams.
Microsoft Teams Rendering surface — where the Adaptive Card is displayed to team members as a native, formatted message.

Value

👁️ Scannable Labelled fields and visual hierarchy let recipients extract the information they need in seconds.
📐 Consistent Every notification from the same template looks identical — regardless of who or what triggered it.
🔗 Actionable Buttons and links embedded in the card give recipients direct access to the issue without searching.
♻️ Reusable One card template with swappable data fields works across all automation use cases.
