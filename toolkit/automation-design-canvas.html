TK-04 Canvas Automation

Automation Design Canvas

Provide a reusable framework for thinking through an automation before building it.

1. WHAT IS THIS?

Use this canvas to move from 'we should automate this' to a clearly defined automation design covering the problem, trigger, data, processing, integration, output, exceptions, security and success.

2. THE CANVAS

1. Problem

  • What manual or repetitive problem are we solving?
  • Who experiences the problem?
  • Why is automation appropriate?
  • What happens if we do nothing?

2. Desired Outcome

  • What should happen automatically?
  • What does success look like?
  • What should no longer require manual intervention?

3. Trigger

  • What starts the automation?
  • Event? Schedule? Status change?
  • User action? Incoming webhook/API call?

4. Source

  • Where does the information originate?
  • Jira, Form, API, Database, Collaboration tool?
  • Another workflow?

5. Input Data

  • What fields/data are required?
  • Which fields are mandatory?
  • What data needs validation?

6. Processing & Logic

  • What decisions must the workflow make?
  • Conditions? Switch/routing?
  • Calculations, Transformations, Aggregation?

7. Integration

  • How do systems communicate?
  • Connector, Webhook, API, HTTP?
  • MCP where applicable?

8. Destination

  • Where does the processed information go?
  • Teams, Slack, Jira, Email, Dashboard?
  • External system?

9. Output / Action

  • What should the automation produce?
  • Notification, Record update, Report?
  • Workflow action, API action?

10. Exceptions & Failure

  • What can fail?
  • What happens when required data is missing?
  • What happens when the destination is unavailable?
  • Who needs to know about failures?

11. Human In The Loop

  • Where is human judgement required?
  • Which actions require approval?
  • What should NOT be automated?

12. Security & Access

  • What credentials/permissions are required?
  • Is sensitive information involved?
  • Are webhook URLs/secrets protected?
  • Is least-privilege access being followed?

13. Monitoring

  • How will we know the automation is working?
  • How are failures detected?
  • Is logging required?

14. Success Measures

  • What manual step was removed?
  • What improvement are we expecting?
  • How will we validate that the automation is useful?

3. HOW TO USE THIS CANVAS

When designing a new automation, work through the canvas in the following suggested sequence:

Problem → Outcome → Trigger → Source/Input → Processing → Integration → Destination/Output → Exceptions → Human Control → Security → Monitoring → Success

4. EXAMPLE

Scenario: Jira Sprint Completion → Teams Summary

Problem & Outcome

  • Problem: Scrum Master spends 30 minutes manually gathering sprint metrics to post in Teams.
  • Outcome: A summary is automatically posted when the sprint is closed.

Trigger & Input

  • Trigger: Sprint state changes to 'Closed' in Jira.
  • Input Data: Sprint Name, Completed Points, Incomplete Points, Goal.

Processing & Integration

  • Logic: Calculate completion percentage. Format as an Adaptive Card.
  • Integration: Jira Automation sends a JSON payload to a Teams incoming webhook.

Output & Exceptions

  • Destination & Output: Delivery Team's Teams Channel notification.
  • Exceptions: If the webhook fails, the Scrum Master receives an email alert.
